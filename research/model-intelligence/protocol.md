# Visual model intelligence protocol

## 1. 纳入标准

一个候选成果至少满足以下两项，才进入正式调研：

- 重做视觉 backbone、视觉编码器或视觉 token 路径；
- 面向高分辨率、多摄像头、多帧、稠密预测或长视觉序列；
- 明确讨论推理延迟、显存、功耗、量化、编译器或硬件；
- 能作为多个视觉任务或 VLM/VLA 的共享视觉底座；
- 提供公开权重、代码、模型卡、消融或真实硬件结果。

仅有新榜单分数、产品宣传、普通 VLM 参数升级或模型名称变化时，不单独建案例。

## 2. 固定问题

### 系统角色

- 输入和输出是什么；
- 它是完整模型还是组件；
- 上游传感器、下游 head、LLM、policy 或控制器是什么；
- 是否包含动作监督或仅提供视觉 token。

### 机制变化

- Backbone 基于标准 ViT、CNN、线性注意力、状态空间模型还是混合结构；
- 是否改动 tokenization、位置编码、多层特征、时空融合或 token compression；
- 理论复杂度降低是否转化为真实 Kernel、内存和端到端收益。

### 训练与数据

- 复用哪个公开 backbone 或 teacher；
- 预训练目标、数据规模、动态分辨率和视频训练方式；
- VLM 是否用于 recaption、过滤、合成监督、蒸馏或错误归因；
- 最大增益来自架构、数据、训练策略还是更大输入。

### 部署证据

- 硬件、精度、batch、输入尺寸和计时范围；
- 是否只报告视觉编码器，还是完整链路；
- 是否存在自定义 Kernel、算子融合和 CPU 回退；
- 是否公布 INT8/FP16、峰值内存、P95/P99、功耗与长期稳定性。

### 对现有工作的迁移

- 检测、关键点、时序建模分别能复用什么；
- 低算力 NPU 应直接部署、改造还是只用作 teacher；
- 需要怎样的最小实验才能区分竞争解释；
- 哪些条件下不应采用该架构。

## 3. 证据等级

| 等级 | 含义 | 可支持的判断 |
|---|---|---|
| E0 | 宣传、采访、二手报道 | 仅作为待核线索 |
| E1 | 官方项目页、技术报告 | 官方定义和自报结果 |
| E2 | 论文、模型卡、代码、权重 | 可检查架构、训练和评测条件 |
| E3 | 第三方复现或同硬件比较 | 可评估外部可重复性 |
| E4 | 本人合法独立实验 | 可形成当前环境内工程判断 |

不得用 E0/E1 支撑“适合某 NPU”“可以替代现有模型”或“端到端更安全”等结论。

## 4. 竞争解释

每个案例至少保留一个机制不同的替代解释，例如：

- 精度提升来自数据质量，而不是新算子；
- 延迟下降来自更少 token，而不是 backbone 更高效；
- 稠密任务提升来自更高输入分辨率，而不是表征更强；
- GPU 自定义 Kernel 的收益不能迁移到固定功能 NPU；
- 视频训练提高了外观稳定性，但没有形成真正时序推理。

## 5. 完成条件

一个案例达到可保留状态，至少应具备：

- 明确的系统角色图；
- 架构、训练、数据、评测和部署摘要；
- 官方事实与本人推断分离；
- 至少一个竞争解释和区分性实验；
- 对现有视觉工作的具体可迁移动作；
- 集中、可访问的第一方来源；
- registry 状态与文档状态一致。

## 6. 更新规则

出现以下情况时必须更新或降级：

- 代码或权重发布后推翻先前架构推断；
- 第三方复现与官方指标显著冲突；
- 新硬件测试改变部署判断；
- 模型被后续版本替代；
- 论文、项目页或仓库失效且无可替代来源。
