# Limitations

## 模型本身的边界

- 密集单阶段检测通常仍受小目标、严重遮挡、模糊、域偏移和标注质量影响；具体程度必须由目标数据验证。
- 多尺度特征并不自动解决低有效像素或不可见目标，输入分辨率提升也可能受算力和训练分布限制。
- NMS-based 分支对置信度、IoU 和类别处理敏感；NMS-free 分支则依赖匹配、训练和导出实现，不能只凭名称判断行为。
- 开放词汇能力受预训练数据、词汇表达、prompt、文本编码器和长尾类别影响，不等于任意类别都能可靠识别。
- 第一方 COCO/LVIS 结果不能直接预测 IR、车载、工业或自定义类别表现。

## 资料和命名的边界

- YOLO 没有统一版本治理机构；相邻编号可能来自不同团队。
- 论文作者实现、维护组织产品分支、第三方框架集成和芯片厂商移植都有各自的权威范围。
- 部分分支主要由源码和在线文档定义，结构说明可能随 release 改变。
- 第一方训练数据、预训练来源、增强细节或导出限制有时未完全披露。
- 聚合网站常把不同 evaluator、硬件和计时范围的数字放在同一表中。
- 当前收录的是主要、可追溯且有实际用途的分支，不穷举所有带 YOLO 名称的论文。

## 部署容易失败的地方

- 预处理颜色、range、padding 或 normalization 不一致；
- exporter、runtime、opset 组合变化；
- head decode、DFL、NMS、端到端选择或视觉—语言节点不受目标 NPU 支持；
- calibration set 与真实输入分布不一致；
- INT8 对分类分数、定位分布、小目标或文本/视觉对齐产生不可接受损失；
- 迁移权重、原始权重和框架重实现混用；
- 只看单图视觉效果，没有任务级、分层和端到端 Oracle。

## 当前还没有完成

- 两个个人案例尚缺完整实验清单、工具链 revision、成对任务指标和延迟边界；
- 尚未冻结所有第一方来源的具体 commit、release 和权重哈希；
- 生态实现尚未经过本人统一精度、维护性和许可复核；
- 尚未完成统一硬件、统一 runtime 的独立复测；
- 目标检测任务页、核心机制页和 YOLO 技术内容尚待本人验收。
